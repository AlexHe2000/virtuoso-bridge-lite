# v1.0.0 — Lite core, optional advanced workflows

The 1.0 release formalizes the project's scope: Spectre execution and PDK/CDF
callback refresh are the core; lightweight schematic, symbol and GDS operations
cover common tasks, with raw SKILL available for the long tail.

Existing single-host configuration remains sufficient. Multiple servers,
accounts, process metadata and profile auditing are optional: no mandatory
matrix, profile selection or migration is introduced.

## Highlights since v0.8.0

- Strict Spectre PSF accessors and more precise OCEAN output controls.
- Split GUI/deployment/daemon/Spectre hosts, safer opt-in first-load bootstrap,
  hardened SSH tunnels and isolated shared-server daemon identity checks.
- Deterministic schematic planning, exact-coordinate manifest import,
  structured diagnostics and transactional import validation.
- Optional SOS operations, lock diagnostics, fail-closed Maestro session state,
  history locks and Monte Carlo helpers.
- Opt-in shared-CIW dialog inspection and authenticated recoverable requests.
  Unknown outcomes retain the original receipt instead of replaying work.
- Explicit profile inventory with source/process metadata and sh/csh environment
  loading, while preserving the simple default configuration.
- Shorter agent/skill entrypoints with focused references and explicit boundaries
  around shared GUI sessions, callback correctness and environment provenance.
- Packaged the default CDF parameter filters in wheels/source archives, with
  distribution-content regression tests in CI to catch missing resources.

## Compatibility and limits

The existing one-host Spectre and SKILL paths remain the default. Advanced
inspection/recovery requires compatible client and daemon capabilities and must
be enabled explicitly. Upgrading the package does not reload an active daemon.
Coordinate any daemon reload in a selected idle CIW.

Legacy bulk dialog dismissal now requires explicit opt-in (`--legacy-bulk` or
`allow_legacy_bulk=True`). Automatic popup dismissal is not a supported shared-CIW
recovery strategy. Configuration-declared process versions are not verified
runtime PDK identity; multi-axis configuration composition remains deferred.

GUI-equivalent electrical results require the same netlist, models, corner and
solver options, plus applicable PDK/CDF callbacks. The version number is not a
claim that every PDK or optional GUI workflow has been electrically validated.

## Validation

- Full offline suite with built-distribution checks: 1,660 passed, 9 skipped on
  Python 3.9 and 3.13. Skips cover unavailable Python 2.7 and explicitly gated
  live IPC/symbol tests.
- Five real Spectre 21.1 jobs: repeated RC decks, consecutive batches with
  `max_workers=1` and `max_workers=2`, and an explicitly owned pool. Parsed
  transient values matched the analytic RC response; output directories were
  distinct.
- The configured CIW daemon endpoint refused the live connection. No daemon
  was reloaded and no user design was modified; live PDK callback/GUI equivalence
  was not established in this release check.
